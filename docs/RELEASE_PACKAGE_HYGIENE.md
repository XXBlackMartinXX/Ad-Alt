# Release Package Hygiene

This document covers the hygiene decisions that affect what ends up inside
the production VSIX and browser extension ZIP — specifically source maps,
the `.vscodeignore` allowlist, and the license situation.

---

## 1. Source Maps

### Decision: OK for beta; exclude before Chrome Web Store submission

Source maps are generated by esbuild during both `build` (production) and
`build:test` (test fixture). They are **not** included in the VSIX.

**VSIX (VS Code extension):** The VSIX is built from `apps/extension/` which
has its own separate `dist/extension.js` and `dist/extension.js.map`. The
`.vscodeignore` now excludes `dist/**/*.map`, `dist/**/*.d.ts`, and
`dist/**/*.d.ts.map`, so source maps are excluded from the VSIX. Re-package
and run `pnpm package:vscode:vsix:audit` to confirm.

**Browser extension ZIP (Chrome Web Store):** The `apps/browser-extension/dist/`
directory is git-ignored. When preparing a Chrome Web Store submission ZIP:
- Do NOT include `dist/*.map` files
- Configure esbuild with `sourcemap: false` OR exclude them from the ZIP script
- Reference the full checklist in section 5 below

**Current beta status:** Acceptable for internal beta. Source map exclusion is
a pre-CWS-submission action item, not a beta blocker.

**Rationale for exclusion before public release:**
- Source maps expose the original TypeScript source to anyone who installs
  the extension, increasing reverse-engineering surface.
- CWS policy does not require source maps; they add unnecessary size.

## 2. `.vscodeignore` Contents

File: `apps/extension/.vscodeignore`

```
src/**
scripts/**
.vscode-test/**
.turbo/**
.gitignore
tsconfig.json
vitest.config.ts
.eslintrc*
dist/**/*.map
dist/**/*.d.ts
dist/**/*.d.ts.map
```

**What each line excludes:**

| Pattern | Reason |
|---------|--------|
| `src/**` | TypeScript source — not needed at runtime; compiled output goes to `dist/` |
| `scripts/**` | Build and dev scripts not needed by the extension consumer |
| `.vscode-test/**` | VS Code extension test runner artifacts |
| `.turbo/**` | Turborepo cache logs. Added after packaging audit revealed `.turbo/` was included, ballooning the VSIX. |
| `.gitignore` | Dev-only file |
| `tsconfig.json` | Dev-only |
| `vitest.config.ts` | Dev-only |
| `.eslintrc*` | Dev-only |
| `dist/**/*.map` | Source maps — expose TypeScript source; excluded from Marketplace submission |
| `dist/**/*.d.ts` | TypeScript declaration files — not needed at runtime |
| `dist/**/*.d.ts.map` | Declaration source maps — not needed at runtime |

**What is NOT excluded (intentionally included):**
- `package.json` — required by VS Code extension runtime
- `dist/extension.js` — compiled extension output (non-map files)
- `LICENSE` (if present) — required for marketplace compliance

### Verifying the VSIX contents

```powershell
# Unzip the VSIX and list its files
Expand-Archive promptprofit-*.vsix -DestinationPath vsix-contents -Force
Get-ChildItem -Recurse vsix-contents | Select-Object FullName
```

After packaging, confirm that `.turbo/`, `src/`, and `scripts/` are absent.

## 3. License

**Current status:** No `LICENSE` file is present in the repository root.

The `package.json` at the root uses `"license": "UNLICENSED"`. This is
intentional for a proprietary project and suppresses the `npm warn` about
missing license that appears when packaging with some tools.

**Important:** The Chrome Web Store and VS Code Marketplace both require a
license declaration. Before public release:

1. Add a `LICENSE` file to the repository root (e.g., a proprietary license
   or a chosen open-source license).
2. Ensure all workspace `package.json` files reference the same license string.
3. Verify that no third-party dependencies carry incompatible licenses. Run
   `pnpm licenses list` to audit dependency licenses.

**Current dependency licenses (spot check):**
All runtime dependencies (`@ad-alt/platform-core`, Playwright, Vitest, esbuild)
are either MIT or Apache-2.0. No GPL or AGPL dependencies are present in the
browser extension workspace.

## 4. What the VSIX Should Never Contain

| Item | Risk | Mitigation |
|------|------|------------|
| `.env` files | API keys / secrets | Git-ignored; `.vscodeignore` would catch if added |
| `dist-test/` | Test fixture bundle with localhost permissions | Lives only in `apps/browser-extension/`, not `apps/extension/` |
| `test-results/` | Playwright HTML reports, screenshots, traces | Git-ignored |
| `node_modules/` | Deps not needed at runtime in VSIX | Excluded by default by `vsce` |
| `*.map` source maps | Source exposure | Not present in `apps/extension/dist/` |
| `.turbo/` | Turbo cache — can contain build logs | Explicitly excluded via `.vscodeignore` |

## 5. Browser Extension ZIP Checklist

When preparing a Chrome Web Store submission:

- [ ] Build from a clean working tree: `git clean -fdx dist/` → `pnpm build`
- [ ] Verify no `.map` files in `dist/` (they are excluded by `package:browser:beta`)
- [ ] Generate placeholder or final icons: `pnpm icons:create` (or use final brand assets)
- [ ] Run `pnpm package:browser:beta` to create the ZIP
- [ ] Run `pnpm package:browser:zip:audit` to verify ZIP contents (internal-beta)
- [ ] Run `pnpm package:browser:zip:audit -- --mode public-release` before CWS submission
- [ ] Verify `manifest.json` version matches `package.json` version
- [ ] `host_permissions` matches intended scope (production manifest should
      NOT include `http://127.0.0.1:*/*`)
- [ ] `content_scripts` matches — only `chatgpt.ts`, not `fixture-test.ts`
- [ ] Confirm `dist-test/` is not included in the ZIP
- [ ] Run `pnpm smoke:chatgpt:fixture` one final time before submission
- [ ] LICENSE file present and matches `package.json` license field (run `pnpm check:license`)

## 6. Artifact Audit Scripts

| Script | Command | Purpose |
|--------|---------|---------|
| `audit-browser-extension-package.js` | `pnpm package:browser:audit` | Checks `dist/` directory contents pre-ZIP |
| `audit-browser-extension-zip.js` | `pnpm package:browser:zip:audit` | Reads ZIP Central Directory; checks forbidden content and required files |
| `audit-vsix-artifact.js` | `pnpm package:vscode:vsix:audit` | Reads VSIX (ZIP format); checks forbidden content |
| `check-license-decision.js` | `pnpm check:license` | Verifies LICENSE decision status without making a choice |
| `check-billing-reconciliation-readiness.js` | `pnpm check:billing:reconciliation` | Checks staging billing readiness |

All audit scripts support `--mode internal-beta` (default, WARNs on blockers) and `--mode public-release` (FAILs on blockers, exits 1).
