# PromptProfit — Internal Beta Monetization Docs

**Directory:** `docs/internal-beta/monetization/`

This directory contains the full internal beta monetization readiness and
pilot rehearsal packet. **Nothing here claims public release, production,
or real-payout readiness** — those remain explicitly blocked; see
`GO_NO_GO_INTERNAL_PILOT_REHEARSAL.md` §3 for the current gate status.

All data referenced or generated by these docs is synthetic (test
advertisers, test developers, fixed fake accounts on the reserved
`example.test` domain). No real money moves anywhere in this codebase —
no payment processor is integrated.

## Recommended reading order

1. **[INTERNAL_BETA_MONETIZATION_READINESS.md](./INTERNAL_BETA_MONETIZATION_READINESS.md)**
   — start here. Current runtime/billing status, what's ready, what's
   not, pilot constraints, accepted risk.
2. **[MONETIZATION_SOURCE_AUDIT.md](./MONETIZATION_SOURCE_AUDIT.md)**
   — the source-code audit everything else is built on: what's billable,
   how splits work, duplicate/replay protection, what's schema-only vs.
   actually implemented.
3. **[LEDGER_CONFIDENCE_REPORT.md](./LEDGER_CONFIDENCE_REPORT.md)**
   — generated by `pnpm -w run check:ledger:confidence`. Deterministic
   proof of split-math, dedup, replay, concurrency, and privacy
   invariants using the real production ledger/fraud code.
4. **[PAYOUT_SIMULATION_REPORT.md](./PAYOUT_SIMULATION_REPORT.md)**
   — generated by `pnpm -w run simulate:payouts`. Synthetic payout-batch
   projection (payable/pending/held/manual_review), simulation only.
5. **[MONETIZATION_PRIVACY_REVIEW.md](./MONETIZATION_PRIVACY_REVIEW.md)**
   — privacy verification for the monetization pipeline; backed by
   `pnpm -w run check:monetization:privacy`.
6. **[BILLING_RECONCILIATION_REPORT.md](./BILLING_RECONCILIATION_REPORT.md)**
   — reconciles the ledger-confidence and payout-simulation runs against
   each other; feeds `pnpm -w run check:billing:reconciliation -- --mode internal-beta`.
7. **[FRAUD_ABUSE_CONTROLS.md](./FRAUD_ABUSE_CONTROLS.md)**
   — review of duplicate/replay/fraud/rate-limit/kill-switch/audit-log
   controls, with severity-rated gaps.
8. **[MONETIZATION_RISK_REGISTER.md](./MONETIZATION_RISK_REGISTER.md)**
   — every open risk across billing, reconciliation, payout, fraud,
   privacy, and operational categories, with severity and status.
9. **[FIRST_MONETIZATION_PILOT_CHECKLIST.md](./FIRST_MONETIZATION_PILOT_CHECKLIST.md)**
   — pre-pilot checklist: advertiser/developer/API-key setup, event/
   ledger/reconciliation/payout verification, rollback plan.
10. **[PILOT_REHEARSAL_PLAN.md](./PILOT_REHEARSAL_PLAN.md)**
    — the operational plan for the synthetic-data pilot rehearsal: scope,
    roles, event/billing/ledger/reconciliation/payout flow, stop
    conditions, go/no-go criteria.
11. **[PILOT_REHEARSAL_REPORT.md](./PILOT_REHEARSAL_REPORT.md)**
    — generated by `pnpm -w run pilot:rehearsal`. The actual rehearsal run
    result: scenario-by-scenario PASS/FAIL, billing totals, payout
    statuses, reconciliation, privacy, and a final PASS/HOLD/STOP decision.
12. **[INTERNAL_PILOT_OPERATOR_RUNBOOK.md](./INTERNAL_PILOT_OPERATOR_RUNBOOK.md)**
    — practical, non-engineer-friendly instructions for running a
    rehearsal and interpreting the result.
13. **[KILL_SWITCH_AND_ROLLBACK_REVIEW.md](./KILL_SWITCH_AND_ROLLBACK_REVIEW.md)**
    — what can be disabled immediately vs. what needs a code change or
    infrastructure access; billing-stop and serving-stop verification.
14. **[GO_NO_GO_INTERNAL_PILOT_REHEARSAL.md](./GO_NO_GO_INTERNAL_PILOT_REHEARSAL.md)**
    — the final decision record for the pilot rehearsal phase: GO for
    rehearsal complete, with every requirement's evidence listed.

## Quick command reference

```bash
pnpm -w run pilot:rehearsal
pnpm -w run check:ledger:confidence
pnpm -w run check:monetization:privacy
pnpm -w run simulate:payouts
pnpm -w run check:billing:reconciliation -- --mode internal-beta
pnpm -w run check:secrets:local
```

All six should exit cleanly (no error) before relying on any report in
this directory as current evidence — per
`INTERNAL_PILOT_OPERATOR_RUNBOOK.md` §15, a stale report left over from a
previous run is never sufficient evidence on its own.
