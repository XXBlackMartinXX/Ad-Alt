## Known limitations

1. This script uses a synthetic in-memory harness for orchestration
   (dedup, balances, click-eligibility), not a live Postgres/Redis --
   because `apps/api`'s real `LedgerService`/`EventProcessor` import
   `@ad-alt/database`, which requires a live `DATABASE_URL` at import time.
2. The REAL orchestration code (`LedgerService`, `EventProcessor`) is
   exercised separately, against a real-code-path in-memory fake DB/Redis,
   by `apps/api/src/__tests__/ledger-balance.test.ts` and `events.test.ts`
   (run via `pnpm -w run verify`) -- this report does not replace those tests.
3. No real Postgres transaction/crash-atomicity is exercised here; that
   requires a staging environment per
   `docs/PRODUCTION_BILLING_RECONCILIATION_PLAN.md`.
4. No refund/void or real payout code paths exist to test (confirmed
   absent in `docs/internal-beta/monetization/MONETIZATION_SOURCE_AUDIT.md`).
5. This report is regenerated by re-running the script; it is not hand-edited.
